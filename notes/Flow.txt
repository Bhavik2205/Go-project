Project Task Flow: File-by-File Development Path
Goal: Build the backend piece by piece, ensuring functionality at each major step.

Phase 0: Project Setup & Initial Structure (Non-Code / Planning)
These are preparatory steps before diving into Go code.

Understand the Overall Architecture:

Files: README.md, structure.txt, notes/
Task: Thoroughly read and understand the detailed system flow you've designed. Familiarize yourself with the folder structure and purpose of each directory.
Validation: You have a clear mental model of how the system will work.
Define Configuration Schemas:

Files: configs/app.yaml, configs/database.yaml, configs/zerodha.yaml, configs/model.yaml, configs/strategy.yaml
Task: Define the initial structure and default values for all your configuration YAML files. Don't worry about perfect values yet, just the keys and expected data types.
Validation: All configs/*.yaml files exist and have placeholder structures for their respective settings.
Environment Variable Setup:

Files: .env (template, DO NOT COMMIT TO GIT), .gitignore
Task: Create a .env file (e.g., .env.example) with placeholder values for all sensitive environment variables (API keys, secrets, DB passwords). Add .env to .gitignore.
Validation: .env file exists with placeholders, and it's ignored by Git.
Containerization Setup:

Files: Dockerfile, configs/docker-compose.yaml
Task: Create a basic Dockerfile for your Go application. Set up docker-compose.yaml to bring up PostgreSQL, Redis, Prometheus, and Grafana. Start with just PostgreSQL and Redis initially for easier debugging.
Validation: docker-compose up successfully starts PostgreSQL and Redis containers. You can connect to them from your machine.
Phase 1: Core Utilities & Database Foundation
This phase builds the essential backbone services.

1. Configuration Loader & Logger
* File: internal/utils/config.go
* Task: Implement LoadConfig() to parse configs/*.yaml files and read environment variables from .env. Define the Config struct that holds all loaded settings.
* Validation: Write a small temporary main.go (or a unit test) to call LoadConfig() and print the loaded configuration, verifying all values are read correctly.
* File: internal/utils/logger.go
* Task: Implement an opinionated logger (e.g., using logrus or zap if you choose, or just log package with prefixes for now). Provide functions like Info, Error, Debug.
* Validation: Use the temporary main.go to test logging messages at different levels.
* File: internal/utils/errors.go
* Task: Define common custom error types or utility functions for error handling.
* Validation: Simple compilation.

2. Database Models & Migrations
* File: internal/db/models.go
* Task: (Already validated!) Implement all GORM structs you've defined (User, UserBrokerAccount, Instrument, MarketData, Order, Trade, Position, NewsArticle, UserStrategy, Metric). Ensure gorm:"primaryKey", gorm:"uniqueIndex", gorm:"not null" tags are correct.
* Validation: No compilation errors.
* Files: internal/db/migrations/000001_create_users_table.up.sql, 000001_create_users_table.down.sql (and other initial migrations)
* Task: Write the SQL migration files for the User and UserBrokerAccount tables. Include the pre_migration_enable_timescaledb.sql as your very first migration.
* File: scripts/db_migrate.sh
* Task: Write the shell script to execute migrate tool (e.g., go-migrate/migrate or golang-migrate/migrate) against your PostgreSQL instance using the internal/db/migrations files.
* Validation: Run scripts/db_migrate.sh up. Verify tables are created in your PostgreSQL database.

3. Database & Redis Clients
* File: internal/db/postgres.go
* Task: Implement NewPostgresClient() function that establishes a GORM connection pool using settings from Config. Add a Close() method if GORM needs explicit closing.
* Validation: In cmd/main.go, call NewPostgresClient() and handle potential errors. Verify connection.
* File: internal/cache/redis.go
* Task: Implement NewRedisClient() function that establishes a go-redis client connection pool using settings from Config. Add a Close() method.
* Validation: In cmd/main.go, call NewRedisClient(), perform a client.Ping(), and check for errors.

4. Initial cmd/main.go & Graceful Shutdown
* File: cmd/main.go
* Task: Integrate all the components from Phase 1. Load config, initialize logger, DB, and Redis. Implement the graceful shutdown logic for SIGINT/SIGTERM using http.Server.Shutdown() as discussed.
* Validation: Run go run cmd/main.go. Verify logs show successful initialization. Press Ctrl+C and ensure the application shuts down gracefully, with DB and Redis connections closing cleanly.

Phase 2: Authentication & User Management (Core APIs)
This phase focuses on user interaction and account linking.

1. Authentication Logic
* File: internal/auth/auth.go (create this file/package)
* Task: Implement functions for RegisterUser, LoginUser (hashing passwords, JWT generation/validation), GenerateJWT, ValidateJWT. Integrate with internal/db/postgres.go (specifically User model).
* Validation: Write unit tests for user registration, login, and JWT token validation.

2. User API Handlers
* File: internal/api/handlers/auth_handlers.go (create this file/package)
* Task: Implement HTTP handlers for /signup (POST), /login (POST). These handlers will use functions from internal/auth/auth.go.
* Validation: Use curl or Postman to test signup and login endpoints. Verify user data and JWTs are created correctly in the database.

3. HTTP Server Routing
* File: internal/server/routes.go
* Task: Set up the gorilla/mux (or chosen router) and define the routes for your authentication handlers. Include JWT middleware for authenticated routes.
* Validation: Ensure your /signup and /login endpoints are accessible via HTTP.

4. Zerodha OAuth & Account Linking
* File: internal/api/zerodha.go
* Task: Implement the Zerodha API client for the OAuth flow:
* Function to generate the login URL.
* Function to exchange request_token for access_token and public_token.
* File: internal/api/handlers/zerodha_oauth_handlers.go
* Task: Implement handlers for /user/broker/zerodha/connect (redirect to Zerodha) and the /api/zerodha/callback endpoint (receives request_token, exchanges it, encrypts, and stores access_token and public_token in UserBrokerAccount via internal/db/postgres.go).

Phase 3: Broker Integration - Instrument Data
This is the first step in getting market data into your system.

1. Instrument Data Fetching
* File: internal/api/instruments.go
* Task: Implement a function to fetch the complete list of tradable instruments from Zerodha Kite Connect API.
* File: internal/db/postgres.go (or a dedicated internal/db/instrument_repo.go)
* Task: Implement logic to store/update instruments in the Instrument table. Use the InstrumentToken as the primary key and handle updates for existing instruments.
* Task: Create a goroutine in cmd/main.go that periodically calls internal/api/instruments.go to fetch and update instruments. This goroutine should respect the shutdown context.
* Validation: Run the bot. Check logs for instrument fetching. Verify instruments table in DB is populated and updated.

Phase 4: Real-time Market Data Ingestion
This is the core of your real-time data pipeline.

1. Zerodha Kite Ticker Client
* File: internal/api/ticker.go
* Task: Implement a WebSocket client that connects to Zerodha Kite Ticker. Handle connection, reconnection, and receiving raw tick data. It should expose a channel to send raw ticks to the next component. This needs to be multi-user aware (e.g., manage a ticker connection per active user or aggregate).
* Validation: Connect to the ticker, print raw tick data to console.

2. Market Data Ingestion Pipeline
* File: internal/data/ingest.go
* Task: Implement functions to:
* Receive raw ticks from internal/api/ticker.go's channel.
* Aggregate ticks into OHLCV bars (e.g., 1-minute bars).
* Calculate basic technical indicators (SMA, RSI, MACD).
* Persist the aggregated MarketData to the market_data hypertable in PostgreSQL (internal/db/postgres.go).
* Publish real-time OHLCV and indicator updates to Redis Pub/Sub (internal/cache/redis.go).
* Validation: Run the ticker and ingest components. Verify market_data table is populating correctly. Use Redis CLI to subscribe to a channel and see market data flowing.

* Logs the order details to the Order table (internal/db/postgres.go).
